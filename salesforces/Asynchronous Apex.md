Here's a comparison table of the four async Apex patterns:

| | **Future Method** | **Queueable Apex** | **Batch Apex** | **Scheduled Apex** |
|---|---|---|---|---|
| **Definition** | A method annotated `@future` that runs asynchronously in its own thread | A class implementing `Queueable` interface, run via `System.enqueueJob()` | A class implementing `Database.Batchable<sObject>`, processes records in chunks via `start`/`execute`/`finish` | A class implementing `Schedulable`, run at a specified time via `System.schedule()` (CRON expression) |
| **Purpose** | Simple, fire-and-forget async tasks — e.g., callouts from a trigger, isolating DML from a mixed-DML context | More flexible async jobs — supports non-primitive/complex parameter types, chaining one job to the next, and callouts | Processing large data volumes (thousands to millions of records) that can't fit in one transaction | Running any Apex logic on a recurring or future schedule (e.g., nightly cleanup jobs) |
| **How it's invoked** | Call the `@future` method directly | `System.enqueueJob(new MyQueueableClass())` | `Database.executeBatch(new MyBatchClass(), batchSize)` | `System.schedule('JobName', cronExpr, new MySchedulableClass())` |
| **Can accept parameters** | Only primitive types (and collections of primitives) | Any type, including sObjects and custom objects (since it's a full class, not just a method) | Determined by `start()` query/iterable — not passed as simple params | Determined by the class itself — not passed as simple params |
| **Chaining** | Not supported | Yes — one Queueable can enqueue another from within `execute()` | Not directly (though a batch's `finish()` can kick off another batch) | Not directly (each execution is independent) |
| **Where it appears / monitored** | Doesn't appear in Apex Jobs UI or Flex Queue — essentially invisible except via debug logs | **Apex Jobs** page (Setup → Apex Jobs) | **Apex Jobs** page, plus sits in the **Apex Flex Queue** while waiting to run (up to 100 jobs) | **Scheduled Jobs** page (Setup → Scheduled Jobs); once running, also shows in Apex Jobs |
| **Key governor limits** | Max 50 future calls per Apex invocation; can't call another future method from within one | Max 50 Queueable jobs added per Apex transaction (5 if chained on top of another, per Salesforce's chaining depth limit in some contexts) | Max 5 batch jobs executing concurrently per org; up to 100 jobs can be queued/held in the Flex Queue; default batch size 200 (max 2,000) | Max 100 scheduled jobs (Apex + other scheduled jobs) active in an org at once |
| **Return value / job ID** | None returned | Returns a job Id (`AsyncApexJob`) | Returns a job Id (`AsyncApexJob`) | Returns a job Id representing the `CronTrigger` |
| **Typical use case** | Callout after a trigger fires | Complex single job needing flexible input or chaining, e.g., processing a specific record's related data | Nightly mass data cleanup/update across an entire object | Recurring maintenance job, e.g., "update all Leads with blank LeadSource every night at midnight" |
